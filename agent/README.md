# Sanad Agent — Native Dart Runtime

The Sanad Agent is the native Dart runtime behind
[Sanad Agent](../README.md). It owns model execution, sessions, workspace
context, permissions, tools, MCP servers, skills, memory, scheduling, provider
configuration, and local durable state.

The agent can run on a desktop computer or as a headless service on macOS,
Linux, and Windows. The Flutter client connects to it directly on the same
computer or, when optional hosted connectivity is enabled, through the Sanad
Gateway from another desktop, mobile, or web client.

## Install a release

Most users should install the standalone agent binary from
[GitHub Releases](https://github.com/EastStarAI/sanad-agent/releases/latest)
or use the remote-device command generated by Sanad Client. See
[Install and Use Sanad Agent](../docs/operations/user_guide.md) for
installation, pairing, provider setup, updates, service management, and
removal.

## Develop from source

This section is for contributors. From the repository root:

```bash
cd agent
fvm dart pub get
fvm dart run bin/sanad_agent.dart daemon
```

Run the interactive CLI:

```bash
cd agent
fvm dart run bin/sanad_agent.dart chat
```

Other entry-point commands include `setup`, `login`, `logout`, `service`,
`update`, `version`, and `help`. For the complete source-development workflow,
matched agent/client runtimes, worktree isolation, logs, restart controls, and
Flutter reload support, use the
[Developer Guide](../docs/operations/developer_guide.md).

## Build and verify

Build the native executable:

```bash
cd agent
fvm dart compile exe bin/sanad_agent.dart -o build/sanad
```

Run analysis and tests:

```bash
cd agent
fvm dart analyze
fvm dart test
```

The agent creates its user configuration from an embedded template on first
run. Provider credentials, Sanad authentication, databases, memories, and
other mutable state belong in the user's Sanad Home outside Git.

## Architecture and runtime contracts

The agent entry point composes focused packages:

- `lib/core/` — configuration, identity, provider runtime, and shared models;
- `lib/engine/` — model execution, adapters, tool loops, and steering;
- `lib/capabilities/` — tools, permissions, MCP, and skills;
- `lib/evolution/` — sessions, memory, scheduling, and durable state;
- `lib/interfaces/` — local and hosted transports and client protocols;
- `lib/infrastructure/` — operating-system and voice implementations.
