# دليل إعداد وتشغيل تطبيق Flutter على بيئة Linux (Ubuntu)

هذا الدليل يوضح الخطوات الشاملة التي تم اتباعها لتجهيز بيئة تطوير وتصدير تطبيق Flutter الحالي للعمل على أنظمة Linux (كالمبنية على Debian/Ubuntu)، سواء كان ذلك على جهاز Linux حقيقي مستقل أو داخل بيئة WSL المدمجة في ويندوز.

## 1. تثبيت المتطلبات الأساسية (Prerequisites)
تطبيقات Flutter الموجهة لسطح مكتب Linux تتطلب أدوات بناء خاصة بـ (C++ و CMake) ومكتبات الواجهة الرسومية الأصلية للينكس (GTK).
قم بتنفيذ الأمر التالي في واجهة الأوامر لتثبيت الحزم المطلوبة:
```bash
sudo apt-get update
sudo apt-get install -y clang cmake ninja-build pkg-config libgtk-3-dev liblzma-dev curl unzip git
```

## 2. تثبيت مكتبات الصوت وإدارتها
يتطلب التعامل مع بث وتسجيل الصوت الوصول المباشر لبطاقات ومكتبات الصوت وبرمجياتها (ALSA و PulseAudio) في نظام Linux لتهيئة الصوت بالشكل الصحيح.
**(مهم جداً في بيئة WSL حيث قد تكون هذه الحزم غير مثبتة افتراضياً):**
```bash
sudo apt-get install -y pulseaudio pavucontrol alsa-utils libasound2-dev
```

## 3. تثبيت لغة Rust و أداة Cargo
بعض الإضافات المستخدمة في المشروع (وتحديداً إضافة `bixat_key_mouse`) كُتبت نواتها (Native code) بلغة Rust باستخدام معمارية تُسمى Cargokit. لذلك، يُعد تثبيت مترجم لغة Rust خطوة إجبارية لنجاح البناء (Compilation) على Linux:
```bash
# تثبيت لغة Rust
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
```
بعد التثبيت، يجب التأكد من عمل تحديث لـ bash أو إضافة أداة Cargo لمتغير البيئة الأساسي للنظام:
```bash
export PATH="$HOME/.cargo/bin:$PATH"
```

## 4. إعداد بيئة Flutter
1. يجب التأكد من تفعيل دعم مشاريع سطح مكتب Linux في إعدادات Flutter الخاصة ببيئة الـ Linux:
```bash
fvm flutter config --enable-linux-desktop
```

> **ملاحظات هامة لمستخدمي أداة FVM في بيئات WSL:**
> إذا تم استنساخ المشروع في الويندوز (كتابة ملفات بنهايِات CRLF) وقمت بمحاولة بناءه من داخل WSL، قد تواجه خطأ غريب متعلق بأمر الـ `env` أو `bash\r`. هذا لأن سكربتات الـ SDK الخاصة بـ Flutter تكون محتفظة بتنسيق ويندوز. في هذه الحالة يُفضل استخدام نسخة flutter المثبتة بصيغة أصلية (Native) داخل الـ WSL لتفادي هذه الانقطاعات.

## 5. حالة telemetry والإشعارات في الإصدار الأول
لا يتطلب Sanad Agent `1.0.0` إعداد خدمة telemetry أوpush خارجية على Linux أوأي منصة أخرى.

تستخدم أخطاء Flutter غير المعالجة السلوك الافتراضي للمنصة والـlogger المحلي الحالي. لم يُضف بديل telemetry مؤقت، كما أن نظام الإشعارات مؤجل لما بعد الإصدار الأول.

## 6. البناء النهائي وتشغيل المشروع
بعد إنهاء الإعدادات السابقة داخل مسار المشروع، قم بمسح ملفات الكاش القديمة المتبقية من نظام آخر وابدأ البناء بشكل نظيف:

```bash
fvm flutter clean
fvm flutter pub get
fvm flutter build linux
```

إذا تم البناء بنجاح بنسبة 100٪، يمكنك أخذ النسخة القابلة للتنفيذ (Binary Release) وتشغيل التطبيق عبر المسار التالي:
```bash
./build/linux/x64/release/bundle/sanad-client
```

## 7. تشغيل التطبيق واختباره من خلال Windows (عبر WSL)
إذا كنت تقوم بالتطوير على بيئة عمل Windows وتريد تشغيل النسخة الخاصة بـ Linux لاختبارها مباشرةً دون الحاجة لجهاز Linux منفصل، يمكنك الاستفادة من ميزة (WSLg) الرسومية.

1. افتح موجه الأوامر الخاص بـ Windows (CMD أو PowerShell).
2. تأكد من أن تطبيق **X Server** لا يعترض العرض (في ويندوز 11 يعمل العرض الرسومي تلقائياً).
3. نفذ الأمر التالي لتشغيل التطبيق المترجم مباشرة من داخل بيئة Ubuntu ليظهر كمنفذة (Window) عادية على سطح مكتبك في ويندوز:

```powershell
wsl -d Ubuntu -u developer -- bash -c "export DISPLAY=:0 ; cd ~/sanad-client/build/linux/x64/release/bundle && ./sanad-client"
```
> **تلميح:** تأكد من تغيير اسم المستخدم `developer` والمسار `~/sanad-client` إلى المسار الفعلي واسم المستخدم الخاص بك داخل بيئة الـ WSL.
