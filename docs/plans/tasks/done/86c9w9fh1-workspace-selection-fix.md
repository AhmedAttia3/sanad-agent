# نقطة البداية للمهمة: إصلاح اختيار مساحة العمل (Fixing Workspace Selection)

## الوضع الحالي (Current State)
* **الآلية الحالية**: عند اختيار مساحة عمل (Workspace) في واجهة المستخدم (`sanad-client`)، يتم جلب قائمة المجلدات وهيكل الملفات (Filetree) من الوكيل (`sanadagent-local`).
* **سبب التصميم**: تم اختيار هذه الآلية سابقاً للحفاظ على دعم الواجهة لكافة المنصات (بما في ذلك الويب والموبايل)؛ حيث لو قامت الواجهة بعمل Pick للمسار محلياً على متصفح أو هاتف ذكي، فسينتهي الأمر باختيار مسار من جهاز العميل نفسه بدلاً من الجهاز الذي يعمل عليه الوكيل الفعلي.
* **المشكلة الحالية**:
  1. الوكيل يعيد قائمة المجلدات بشكل غير صحيح؛ فبدلاً من إرجاع كافة المسارات الرئيسية ومحركات الأقراص المتاحة في نظام تشغيل جهاز الوكيل بالكامل لتسهيل الاختيار، فإنه يقوم بإرجاع المجلدات بدءاً من **داخل المجلد الذي تم تشغيل الوكيل فيه فقط** (مما يقيد الاختيار ويمنع المستخدم من تحديد أي مجلد خارج مجلد تشغيل الوكيل).
  2. الواجهة لا تفرق بذكاء بين ما إذا كان الوكيل يعمل محلياً بالكامل على نفس جهاز العميل (Local Agent) وبين ما إذا كان يعمل عن بعد (Remote Agent).

---

## الوضع المستهدف / الهدف (Target State)
* **التوجيه الذكي لاختيار مساحة العمل (Smart Workspace Routing)**:
  * يجب أن تصبح واجهة المستخدم ذكية بما يكفي للتحقق مما إذا كان الوكيل مثبتاً ويعمل محلياً على نفس الجهاز أم لا (من خلال مقارنة معرف الوكيل `agent_id` أو التحقق مما إذا كان التطبيق يعمل على نفس المضيف `localhost`/`127.0.0.1` أو تطابق معرفات الأجهزة).
  * **الحالة الأولى: الوكيل محلي (Local Agent)**:
    * تتجاوز الواجهة استعلام الوكيل للمجلدات، وتستخدم مكتبة Flutter جاهزة لاختيار المجلدات (مثل `file_picker` أو مكتبة النظام الأصلية) لتمكين المستخدم من تصفح واختيار أي مجلد على جهازه مباشرة بواجهة اختيار مجلدات أصلية (Native Folder Picker)، مما يضمن تجربة مستخدم ممتازة وسلسة. ثم يتم إرسال المسار المختار مباشرة إلى الوكيل.
  * **الحالة الثانية: الوكيل بعيد (Remote Agent)**:
    * تستمر الواجهة في استخدام الطريقة الحالية بجلب قائمة المجلدات من الوكيل نفسه عبر الـ API.
    * **إصلاح الوكيل (Fixing Remote Directory API)**: يتم تعديل وإصلاح الـ API المسؤول عن تصفح المجلدات في الوكيل (`sanadagent-local`) بحيث لا يحصر البحث والمسارات داخل مجلد تشغيل الوكيل نفسه. يجب أن يقوم بإعادة محركات الأقراص/المجلدات الرئيسية للنظام بالكامل (مثلاً `/` على أنظمة macOS وLinux، أو محركات الأقراص `C:\`, `D:\` إلخ على أنظمة Windows) لتمكين المستخدم من تصفح جهازه بالكامل واختيار أي مسار.

## حالات الاختبار (Test Cases)
### حالات اختبار واجهة المستخدم (Client UI - Smart Selection Routing):
* **حالة 1**: التحقق من أن الواجهة تكتشف أن الوكيل محلي (Agent Host = localhost / Match Device ID) وتقوم بفتح الـ File Picker الأصلي للجهاز بنجاح عند الضغط على اختيار مساحة العمل.
* **حالة 2**: التحقق من أنه عند تحديد مجلد باستخدام الـ File Picker الأصلي، يتم إرسال المسار المختار بدقة كـ relative path أو absolute path متوافق مع نظام تشغيل الوكيل ويتم تعيينه كمساحة عمل نشطة.
* **حالة 3**: التحقق من أن الواجهة تكتشف أن الوكيل بعيد (Agent Host != localhost) وتقوم باستدعاء الـ API الخاص بالوكيل لاستعراض المجلدات بدلاً من الـ File Picker الأصلي.

### حالات اختبار خادم الوكيل (Agent Server - Directory API Fix):
* **حالة 4 (برمجية/تلقائية)**: اختبار الـ API الخاص بالوكيل للتحقق من أنه عند تمرير مسار فارغ أو طلب جذور النظام، فإنه يعيد جذور نظام التشغيل الفعلية (مثل `/` أو الأقراص المتاحة) وليس مجلد تشغيل الوكيل.
* **حالة 5 (التنقل الآمن)**: التحقق من إمكانية التنقل والتصفح صعوداً وهبوطاً خارج مجلد تثبيت الوكيل عبر الـ API (Directory Navigation) والتحقق من عدم حدوث أخطاء صلاحيات في نظام التشغيل.
