* **عدم وجود عارض ملفات مدمج**: يفتقر التطبيق لوجود شاشة أو تبويبات لعرض محتويات الملفات البرمجية أو النصية وتعديلها عند النقر عليها، مما يعزل المستخدم عن رؤية الكود الفعلي وملفات المشروع بطريقة مرئية أثناء تفاعل الوكيل معها.

## الوضع المستهدف / الهدف (Target State)
* **شجرة تصفح المجلدات الكسولة (Lazy VS Code-like File Tree)**:
  * بناء لوحة جانبية لتصفح المجلدات تحاكي واجهة وتجربة VS Code بالكامل (أيقونات المجلدات والصيغ، المحاذاة، خطوط الإرشاد، وتمييز وتلوين الملفات المضافة أو المعدلة).
  * **التحميل الكسول (Lazy Loading)**: يتم جلب وتصفح المجلدات بشكل ديناميكي؛ بحيث لا يقوم التطبيق بقراءة كامل المجلدات مسبقاً (لتفادي البطء وتجميد الواجهة في المشاريع الكبيرة مثل مجلدات `node_modules` أو `venv`) بل يتم الاستعلام من الديمون وجلب محتويات المجلد الفرعي فقط عند قيام المستخدم بالنقر عليه لتوسيعه.
* **محرر وعارض ملفات تفاعلي ومتطور (Interactive CodeForge Editor)**:
  * عند النقر على ملف في الشجرة الجانبية، يتم فتحه في تبويب مخصص (Tab View) في الواجهة المركزية.
  * **دعم عرض وتحرير الأكواد**: استخدام مكتبة `code_forge` (الإصدار `^5.1.0` المدمج بالفعل في `pubspec.yaml`) لبناء محرر أكواد قوي ومتكامل للقراءة والكتابة يدعم:
    * تلوين الصيغ لأكثر من 180 لغة برمجية.
    * طي الأكواد الذكي (Code Folding).
    * التكامل مع بروتوكول خادم اللغة (LSP Integration) لعرض التلميحات والأخطاء inline.
    * محرك تراجع وإعادة ذكي (Smart Undo/Redo) وتنسيقات سمات متكاملة.
  * **دعم ملفات الماركداون (`.md`)**: توفير خياري عرض مدمجين:
    1. **وضع القراءة التفاعلية المنسقة (Rendered Markdown View)** لعرض النصوص بشكل منسق وجميل.
    2. **وضع التحرير المباشر (Edit Mode)** للتعديل، مع سهولة التنقل بين الوضعين.
  * **دعم الصور**: عارض صور تفاعلي مدمج يدعم التكبير والتصغير.
  * **تكامل الديمون والواجهة**: ربط عمليات القراءة والحفظ عبر بروتوكول المقبس (Socket.IO) بين الواجهة والديمون المحلي لحفظ التعديلات على القرص فوراً وبشكل متزامن.
