# المرحلة الثانية: إعادة التسمية الشاملة وتطهير المصطلحات

> هذه المرحلة هي الخطوة الثانية من أربع خطوات لتحقيق التوجه الجديد للمشروع الموثق في **[وثيقة متملبات المنتج (PRD)](../product/prd_sanad_agent.md)**. تهدف هذه المرحلة إلى القضاء على التداخل والخلط المفاهيمي في المصطلحات المستخدمة داخل الكود وقاعدة البيانات والمستندات قبل الانتقال إلى التغييرات المعمارية العميقة.

---

## الهدف

تطهير المصطلحات وتوحيدها عبر جميع مكونات المنظومة (الباك اند، والواجهة، وبروتوكول الاتصال) لتعكس بدقة النموذج المعماري الجديد:
1. **الفصل بين الجهاز والوكيل:** تحويل مصطلح `Agent` (عندما يشير إلى جهاز التشغيل أو الخادم المتصل) إلى `Device` بشكل كامل في قاعدة البيانات والكود.
2. **توحيد مصطلح الجلسات:** تحويل مصطلح `Thread` إلى `Session` في كل مكان (الواجهة وقاعدة البيانات والاتصالات)، ليتطابق مع المفاهيم الحديثة لواجهات الاستخدام.

---

## النطاق (Scope)

### 1. قاعدة البيانات المركزية (Backend PostgreSQL Database)
- **إعادة تسمية الجداول:**
  - تغيير اسم جدول `agents` إلى `devices`.
  - تغيير اسم جدول `agent_tokens` (إن وجد) إلى `device_tokens`.
- **تحديث الأعمدة والمفاتيح الخارجية (Foreign Keys):**
  - تغيير حقل `agent_id` إلى `device_id` في كافة الجداول المرتبطة (مثل `usage_logs` وأي جداول ربط أخرى).
- **الهجرة (Migrations):**
  - إنشاء Alembic migrations لتطبيق هذه التغييرات برمجياً في قاعدة البيانات.

### 2. الباك اند (FastAPI Backend)
- **نماذج البيانات (Models & Schemas):**
  - إعادة تسمية كلاس `Agent` ORM Model إلى `Device`.
  - إعادة تسمية Pydantic models (مثل `AgentCreate` تصبح `DeviceCreate`).
- **مسارات الـ API (Endpoints):**
  - تحديث الروابط في الـ Routers لتصبح `/api/v1/devices` بدلاف من `/api/v1/agents`.
  - تحديث أسماء الدوال والمتغيرات الداخلية والـ docstrings في الباك اند.

### 3. بروتوكول الاتصال (Socket.IO Events & Payloads)
- **تحديث الأحداث (Events):**
  - تغيير أحداث مثل `agent:connect` أو `agent:disconnect` لتصبح `device:connect` و `device:disconnect`.
  - تغيير أحداث التوجيه والـ proxy لتتوافق مع المصطلح الجديد.
- **حزم البيانات (Payloads):**
  - استبدال المفتاح `agent_id` بـ `device_id` في جميع حزم البيانات المتبادلة بين الواجهة والباك اند والوكيل.

### 4. واجهة المستخدم (`sanad-client`)
- **نماذج البيانات وكود Dart:**
  - إعادة تسمية Model `Agent` إلى `Device`.
  - إعادة تسمية Model `Thread` إلى `Session`.
- **الـ State Management (Cubits/Blocs):**
  - تحديث الـ States والـ Cubits (مثل `AgentCubit` يصبح `DeviceCubit` أو `DeviceRegistryCubit`).
  - تحديث الـ Cubits الخاصة بالـ Threads لتصبح `SessionCubit`.
- **واجهة المستخدم والنصوص:**
  - استبدال أي نصوص معروضة للمستخدم تحتوي على "الوكيل" أو "الوكلاء" بـ "الجهاز" أو "الأجهزة" عند الإشارة للأجهزة المتصلة.
  - استبدال نصوص "Threads" بـ "Sessions" أو "المحادثات".
- **التخزين المحلي:**
  - فحص أي تخزين محلي وتحديث المفاتيح والمصطلحات.

### 5. الوكيل المحلي (`sanadagent-local` مؤقتاً)
- تحديث كود الاتصال بالـ Gateway لاستخدام أحداث الـ Socket الجديدة (`device:connect` بدلاً من `agent:connect`) والـ payload المعادل (`device_id`).
- تحديث المتغيرات الداخلية التي تمثل هوية الجهاز وقاعدة البيانات المحلية إن لزم الأمر لتتوافق مع المصطلحات الجديدة.
